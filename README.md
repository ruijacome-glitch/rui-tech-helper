# Rui's Computer Fix

Cria a homepage completa e funcional de um novo site chamado “O Rui dos Computadores”, para assistência informática local em Cascais, Portugal.

OBJECTIVO
Quero um site de marca pessoal memorável, credível e fora da caixa, que não pareça um template nem um projecto típico de vibe coding. Deve transmitir proximidade, experiência técnica e capacidade de explicar problemas informáticos sem complicações. Nesta fase cria apenas a homepage pública, sem backoffice, sem autenticação, sem dashboard e sem base de dados.

IDENTIDADE E DIRECÇÃO VISUAL
A marca tem uma mascote ilustrada do Rui, técnico de informática de cabelo escuro e barba, com polo azul escuro e computador portátil. Não uses fotografias pessoais nem imagens de bancos de imagem. Como os ficheiros finais da mascote e do logótipo serão enviados depois, cria componentes e espaços próprios para os receber, usando agora uma representação gráfica temporária discreta e claramente substituível.
Paleta principal: azul noite quase preto #030B1A, azul eléctrico #0877FF, laranja vivo #FF7A00, branco quente #F4EFE8 e cinza azulado #8EA3BE.
Tipografia: títulos muito fortes e condensados, ao estilo editorial/industrial, combinados com texto legível e humano. Podes usar Google Fonts adequadas, por exemplo Oswald ou Archivo Narrow nos títulos e Inter no corpo.
O resultado deve equilibrar tecnologia e proximidade. Não deve parecer infantil nem demasiado cartoon.
Evita completamente: gradientes roxos genéricos, blobs decorativos, glassmorphism exagerado, cartões todos iguais com cantos demasiado arredondados, ícones 3D genéricos, fotografias stock, fundos com grelhas artificiais e excesso de sombras.

CONCEITO VISUAL
O fio condutor do site é um “cabo de diagnóstico” azul eléctrico que percorre a página, liga secções e ganha pequenos pulsos de luz ao fazer scroll. Usa SVG e CSS para desenhar este cabo de forma elegante. Acrescenta microinteracções úteis: cursor/ponteiro nos sintomas, pequenos sinais de diagnóstico, indicadores de problema detectado e solução encontrada. As animações devem ser fluidas e subtis, respeitando prefers-reduced-motion.
Combina secções escuras e uma secção clara em branco quente. Usa linhas finas, numeração técnica, etiquetas como “01 // SINTOMAS”, pequenas notas monoespaçadas e assimetria editorial controlada. O site tem de ter personalidade sem perder legibilidade.

NAVEGAÇÃO
Cabeçalho fixo e compacto com espaço para o logótipo circular e wordmark.
Links: Serviços, Como funciona, Para negócios, Sobre o Rui, Preçário, Contactos.
Botão laranja “Pedir ajuda”.
No telemóvel usa menu acessível e simples.

HERO
Fundo azul noite, composição editorial em duas colunas.
Título exacto:
“O TEU COMPUTADOR
NÃO PRECISA DE UM
CALL CENTER.
PRECISA DO RUI.”
A última frase deve surgir em azul eléctrico.
Subtítulo:
“Assistência informática em Cascais, sem complicações e sem conversa técnica.”
CTA principal azul: “Começar diagnóstico”
CTA secundário: “Falar no WhatsApp”
Do lado direito cria uma cena gráfica temporária para a futura mascote do Rui a reparar um portátil, enquadrada por um arco/círculo azul eléctrico. Inclui pequenas etiquetas animadas “A analisar”, “Problema detectado” e “Solução encontrada”.
Não uses a futura carrinha no site. A carrinha laboratório é apenas uma ambição de longo prazo e não pode ser apresentada como serviço ou recurso actual.

FAIXA DE SINTOMAS
Uma faixa horizontal com:
“Está lento • Não liga • Wi-Fi falha • Ficheiros perdidos • Impressora não imprime”
Pode ter movimento horizontal muito lento, mas deve parar ao passar o rato e respeitar acessibilidade.

SECÇÃO 01, DIZ-ME O QUE SE PASSA
Fundo branco quente.
Título: “DIZ-ME O QUE SE PASSA.”
Cinco opções grandes e clicáveis:
1 Computador lento
2 Internet instável
3 Não arranca
4 Perdi ficheiros
5 Preciso de ajuda
Cada opção tem iconografia linear própria, numeração e um estado hover distinto. Ao seleccionar, actualiza uma pequena frase contextual e o CTA “Pedir ajuda sobre isto”, sem backend.
Nota monoespaçada: “RUI: selecciona um sintoma para começarmos.”

SECÇÃO SERVIÇOS
Apresenta os serviços de forma visual e não como seis cartões genéricos:
Reparação de computadores e portáteis
Limpeza e optimização
Instalação e configuração
Recuperação de dados
Apoio remoto
Redes Wi-Fi, impressoras e periféricos
Usa uma composição editorial alternada, com linhas e pequenos diagramas, orientada a benefícios e sem jargão excessivo.

SECÇÃO 02, COMO FUNCIONA
Fundo azul noite.
Processo em três passos ligado pelo cabo animado:
01 “Explicas” — “Sem linguagem técnica. Dizes o que se passa.”
02 “Diagnostico” — “Analiso o problema e identifico a causa.”
03 “Resolvo” — “Aplico a solução certa e confirmo contigo.”
Usa círculos numerados, bastante espaço e animação de progressão ao fazer scroll.

SECÇÃO 03, PORQUÊ O RUI
Faixa de credibilidade com quatro argumentos:
“Desde 2006 — A resolver problemas de informática.”
“Cascais — Local, disponível e de confiança.”
“Ao domicílio — Vou até ti. Tu ficas descansado.”
“Particulares e pequenos negócios — Soluções à medida do que precisas.”
Inclui um bloco de testemunho visual, mas não inventes nomes nem opiniões reais. Usa texto editorial assinalado como exemplo substituível no código, por exemplo “Finalmente alguém que explica sem complicar”, e marca claramente os dados como conteúdo a validar antes da publicação.
Inclui também um pequeno terminal visual “RUI_OS v3.1” com resultado “Resolvido”, apenas como elemento de marca, não como dashboard.

SECÇÃO PARA PEQUENOS NEGÓCIOS
Explica que o Rui também ajuda pequenos negócios de Cascais com computadores, redes Wi-Fi, impressoras, postos de trabalho e apoio próximo. Sem contratos complicados e sem linguagem empresarial vazia.
CTA: “Falar sobre o meu negócio”.

SECÇÃO PREÇÁRIO
Cria uma secção visualmente completa chamada “PREÇOS CLAROS, SEM SURPRESAS”.
Não inventes valores. Implementa os preços como uma constante/array fácil de editar e mostra temporariamente três entradas com “Valor a confirmar”:
Diagnóstico
Assistência remota
Assistência ao domicílio
Acrescenta “O valor é sempre confirmado antes de avançar.”
Esta secção será preenchida com os valores finais numa iteração seguinte.

CTA FINAL
Faixa azul eléctrico muito forte.
Título: “O PROBLEMA NÃO SE VAI RESOLVER SOZINHO.”
Grande botão circular laranja “Chamar o Rui”.
Texto lateral: “Resposta rápida. Solução próxima.”
Botão WhatsApp e alternativa de formulário.

CONTACTOS
Cria um formulário simples apenas de interface com Nome, Contacto, O que se passa e preferência “WhatsApp / Telefone / Email”. Validação no cliente e mensagem de sucesso simulada, sem enviar dados.
Não inventes telefone, email ou morada. Centraliza estes dados num objecto de configuração e mostra “Contacto a adicionar” onde necessário.
Indica apenas “Cascais e arredores” como área de atendimento.

RODAPÉ
Espaço para logótipo, Cascais, WhatsApp, links principais, política de privacidade e a assinatura discreta:
“RUI_OS v3.1 — obrigado pela confiança.”

REQUISITOS DE IMPLEMENTAÇÃO
Homepage totalmente responsiva, excelente em desktop e telemóvel.
React + TypeScript + Tailwind, componentes bem organizados e dados editáveis separados do layout.
Acessibilidade: contraste AA, navegação por teclado, foco visível, labels, aria quando necessário.
SEO base em português: title, description, headings correctos e conteúdo sem lorem ipsum.
Todo o texto visível em Português de Portugal. Não uses construções ou vocabulário do português do Brasil.
Não publiques o site ainda.
No final, verifica visualmente que não existem secções vazias, elementos cortados, texto sobreposto ou scroll horizontal.

## Deploy (cPanel, sem SSH)

cPanel shared hosting não tem runtime Node/Workers, por isso o site é prerenderizado
para HTML estático (`nitro` preset `static`) e só o output já construído é enviado
para o servidor — o build corre sempre localmente ou em CI, nunca no cPanel.

1. cPanel → Git Version Control → clonar este repo em `/home/mercadom/repositories/rui-tech-helper`.
2. Antes de cada push para `main`: `npm run deploy:prepare` — corre o build estático e
   copia `.output/public/` para `static-dist/` (tracked em git, ao contrário de `.output/`).
   Por omissão substitui `static-dist/index.html` pela página `/em-construcao`, para o
   site público mostrar apenas "em construção" até à migração de dados real (ponto 5 do
   roadmap). Para publicar o site completo: `CONSTRUCTION_MODE=false npm run deploy:prepare`.
3. Commit + push `static-dist/` para `main` + "Update from Remote" no cPanel corre
   `.cpanel.yml`, que faz rsync de `static-dist/` para a docroot.
4. `npm run build` sozinho (sem o wrapper `deploy:prepare`) já é seguro de correr
   isoladamente — ignora um crash conhecido e inofensivo do build final do Nitro que
   acontece depois de todo o HTML estático já ter sido escrito (bug upstream do preset
   `static`, não do código deste projecto).
